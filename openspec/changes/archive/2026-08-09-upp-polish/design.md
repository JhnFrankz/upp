# Design: upp-polish — Post-rewrite polish (docs, CI, release pipeline, format, adapter tests)

## Technical Approach

Non-functional change (Capabilities None/None). Four independent tracks, each a revertible commit: (1) docs + registry + `openspec/config.yaml` commits, (2) CI workflow + `make release`/`install`, (3) `gofmt -s` commit on 9 files, (4) hermetic table-driven adapter tests via a test-only exec seam in `helper.go`. No product behavior changes; verify via `go test ./... -count=1`, `gofmt -s -l .`, coverage ≥80% on `internal/adapters/official`.

## Architecture Decisions

### D1: Exec seam — package-level function vars in `helper.go`

| Option | Tradeoff | Decision |
|---|---|---|
| Function vars (`runCmdFn`, `runCmdArgsFn`, `lookPathFn`) swapped by tests | Minimal diff, hermetic, deterministic; slight indirection | **Adopt** |
| Fake binaries on `PATH` in `t.TempDir()` | No prod change, but shell commands (`sh -c "apt-cache policy…"`) resolve the REAL `apt` — env-dependent, breaks on CI | Reject |
| Per-adapter injected runner | Invasive signature changes across 12 adapters | Reject |

Rationale: adapters already funnel through 3 leaf functions in `helper.go`; wrappers (`shellOutput`, `commandOutput`) stay real and are covered through the leaf fakes. Restore vars in `t.Cleanup`.

### D2: Test organization — method-grouped cross-adapter tables

| Option | Tradeoff | Decision |
|---|---|---|
| `exec_mock_test.go` + `check_test.go`/`update_test.go`/`detect_info_test.go`, one table per method with per-adapter sub-tests | Shared seam, minimal boilerplate, named cases | **Adopt** |
| Per-adapter files mirroring prod | Mirrors layout; high duplication | Reject |

Rationale: tables share the same fakes; adapter identity lives in `t.Run(name, …)`.

### D3: Release automation level

| Option | Tradeoff | Decision |
|---|---|---|
| `make release` = build-all + tar/zip assets + `checksums.txt`; no tag, no publish | Pipeline ready, zero publish risk; user triggers first tag manually | **Adopt** |
| Auto-tag + `gh release create` | One command, but publishes a real release — violates "no real release" | Reject |

### D4: CI jobs split (`.github/workflows/ci.yml`, new)

| Option | Tradeoff | Decision |
|---|---|---|
| Split `test` / `lint` / `release` jobs | Parallel, clear failure attribution | **Adopt** |
| Single monolithic job | Fewer runners; no isolation | Reject |

Pin `ubuntu-latest` + Go 1.22, `actions/setup-go` with `cache: true` (module cache). `test`: checkout → setup-go → `go vet ./...` → fmt gate (`test -z "$(gofmt -s -l .)"`) → `go test ./... -count=1` → `go test -race` → build + `bash scripts/smoke-test.sh --skip-build`. `lint`: `golangci/golangci-lint-action` (latest). `release`: triggers on `workflow_dispatch` + tag `v*`; runs `make release`, uploads `dist/**` via `actions/upload-artifact`; NO publish step.

### D5: Makefile additions

`release` (`.PHONY`): depends on `build-all`, then per-platform `tar czf` for unix targets, `zip` for windows, and checksums via `sha256sum` (fallback `shasum -a 256`); no git tag, no push. `install`: `go build` + `install -m 0755` to `PREFIX` (default `/usr/local/bin`, override via `PREFIX=… make install`). No sudo; documented in README.

## Data Flow

```
push/PR ──► test job: vet → fmt gate → go test -count=1 → race → smoke ──► ✅
push/PR ──► lint job: golangci-lint ──► ✅
tag v* / dispatch ──► release job: make release ──► dist/*.{tar.gz,zip} + checksums.txt ──► artifact (unpublished)

Test: table row ──► setExecFakes(t, …) ──► adapter method ──► runCmdFn/… fake ──► assert (no exec)
```

## Interfaces / Contracts

```go
// helper.go — test seam (only prod change)
var (
    runCmdFn     = runCmd
    runCmdArgsFn = runCmdArgs
    lookPathFn   = lookPath
)

// exec_mock_test.go
type fakeResult struct{ stdout, stderr string; err error }
type execFakes struct {
    shell    map[string]fakeResult // full command string
    cmdArgs  map[string]fakeResult // by binary name
    lookPath map[string]bool
}
func setExecFakes(t *testing.T, f execFakes) // swaps vars, t.Cleanup restore
```

Per-adapter case matrix (all mocked, no real commands): **detect** — `lookPath` true/false (nvm: `NVM_DIR` present/absent); **check** — version output: normal, empty→`"unknown"`, multiline, pre-release (apt: `apt-cache policy` installed/candidate rows incl. `(none)`; npm/pnpm/bun: `outdated` output present/absent); **update** — dry-run shortcut, command error, stderr marker (`E:`/`ERR!`/`error`), success with before/after; **info** — golden ID/name/platforms/trust. Docker: update success + error on current `runtime.GOOS` branch only (GOOS not mockable — other branches stay uncovered). Replace `TestDryRunDoesNotExecute` and all skip-if-absent dry-run tests.

## Testing Strategy

| Layer | What to Test | Approach |
|---|---|---|
| Unit | 12 adapters × detect/check/update/info + error paths | Table-driven via `setExecFakes`; package gate ≥80% |
| Integration | CLI unchanged; smoke script | CI job reuses `scripts/smoke-test.sh` |
| E2E | None — no product behavior change | N/A |

## Threat Matrix

No product routing, subprocess, VCS/PR automation, or executable-classification boundary changes — adapters execute no real subprocesses in tests, and `make release`/CI are user-triggered declarative infra, not adversarial input handlers.

| Boundary | Applicability | Reason |
|---|---|---|
| Documentation-like paths | N/A | No classification/execution of doc files |
| Git repo selection | N/A | Makefile tags nothing; no `git -C`/path handling |
| Commit state | N/A | No commit automation |
| Push state | N/A | No push automation |
| PR commands | N/A | No PR automation |

## Migration / Rollout

No migration. Commit sequence (independent, revertible): (1) `chore:` commit `openspec/config.yaml` + registry refresh (10 sdd-* skills); (2) `style:` `gofmt -s -w` (9 files — separated from tests, per proposal); (3) `docs:` README rewrite; (4) `ci:` workflow; (5) `build:` Makefile release/install; (6) `test:` exec seam + tables. Deleting the workflow file fully disables CI. Forecast: test-track commits far exceed the 400-line review budget → chain PRs by track.
